# Notion Sync 管理者 UI 利用ガイド

## 概要

Notion Sync 管理者 UI は、Salesforce 管理者がカスタムメタデータを直接編集することなく、本パッケージの 2 つの機能を設定できる Lightning Web コンポーネントです。

- **Sync**: Salesforce のオブジェクトと項目を Notion データベースにマッピングします。
- **Widgets**: Lightning ページに埋め込み可能な Notion データベースを基にしたウィジェットを設定します。

いずれの機能も、**Notion Sync** アプリケーション内の同じ管理者タブで提供され、サブタブに分かれています。

> インストールから初期設定までの一連の手順については、[SETUP_GUIDE.md](./SETUP_GUIDE.md) を参照してください。本ドキュメントは、管理者 UI の各操作要素のリファレンスです。

## 管理者 UI へのアクセス

1. アプリケーションランチャー（9 点のグリッドアイコン）をクリックします。
2. **Notion Sync** を検索し、アプリケーションを開きます。
3. アプリケーションには以下の 2 つのトップレベルタブが含まれます。
   - **Notion Sync Admin** — メインの設定インターフェース（Sync / Widgets / Settings のサブタブ）。
   - **Notion Sync Log** — 直近の同期試行とそのステータス。

別のアプリケーションでもこれらのタブを表示するには、設定 → **アプリケーションマネージャー** → **ナビゲーション項目** で編集し、`Notion Sync Admin` と `Notion Sync Log` を追加してください。

## 権限セット

本パッケージには 3 つの権限セットが同梱されています。必要なユーザーにそれぞれ割り当ててください。

| 権限セット | ラベル | 必要なユーザー |
|---|---|---|
| `Notion_Sync_Admin` | Notion Sync Administrator | 同期マッピングやウィジェットを設定する管理者。 |
| `Notion_Integration_User` | Notion Integration User | レコードの変更をフロー経由で同期トリガーするユーザー。 |
| `Notion_Widget_User` | Notion Widget User | Lightning ページ上で埋め込みウィジェットを閲覧するだけのエンドユーザー。 |

割り当て手順：

1. 設定 → **権限セット** → 権限セット名をクリックします。
2. **割り当ての管理** → **割り当ての追加** → ユーザーを選択 → **割り当て** をクリックします。

Notion Sync Administrator 権限セットには、カスタム権限 `Notion_Sync_Admin`、Notion 外部ログイン情報へのアクセス、本パッケージのすべてのカスタムメタデータ型への読み取りアクセス、メタデータをデプロイするために必要なユーザー権限（アプリケーションのカスタマイズ、メタデータの変更）、および同期ログへの読み取り専用アクセスが含まれます。

1 人のユーザーが複数の権限セットを保持することも可能です。レコードを編集して同期をトリガーする管理者には、Administrator と Integration User の両方が必要となるのが一般的です。

## 管理者 UI のレイアウト

**Notion Sync Admin** タブは 3 つのサブタブで構成されています。

| サブタブ | 用途 |
|---|---|
| **Sync** | オブジェクトとデータベースのマッピング、項目マッピング、リレーションシップを設定します。 |
| **Widgets** | Lightning ページに埋め込み可能な Notion データベースを基にしたウィジェットを設定します。 |
| **Settings** | Notion 接続のテストやパッケージレベルのオプションを表示します。 |

ページ上部にある **Test Connection** アクションはどのサブタブからでも利用でき、指定ログイン情報のアクセスとデータベースの可視性を検証します。

## Sync サブタブ

### 同期設定の一覧

Sync サブタブには、既存の同期設定が概要統計（設定済みオブジェクト数、有効な同期数、項目マッピングの合計数）とともに表示されます。各行には、Salesforce オブジェクト、リンクされた Notion データベース、有効状態、項目およびリレーションシップマッピングの件数が表示され、行ごとに **Edit** アクションが用意されています。

新しいマッピングを作成するには、**New Sync Configuration** をクリックします。

### 同期設定の作成

1. **New Sync Configuration** をクリックします。
2. ドロップダウンから Salesforce オブジェクトを選択します。
3. **Active** を切り替えます（デフォルトで有効）。
4. **Browse Databases** をクリックして、対象の Notion データベースを選択します。データベースは事前に Notion 側でインテグレーションに共有されている必要があります。
5. **Salesforce ID Property Name** を選択します。これはパッケージが Salesforce レコード ID を保存する Notion のテキストプロパティです。このプロパティは Notion データベース上に事前に存在している必要があるため、ない場合はまず追加してください。
6. 保存します。項目マッピングは後から戻って追加できます。

### 同期設定の編集

既存の設定を開くと、3 つのセクションが表示されます。

- **Basic Configuration** — 有効状態の切り替え、Notion データベースの変更、Salesforce ID プロパティ名の変更を行います。
- **Field Mappings** — Salesforce 項目と Notion プロパティ間のマッピングを追加します。UI は Salesforce 項目タイプごとに互換性のある Notion プロパティ型を自動で提案します（[自動型検出](#auto-type-detection) を参照）。ロングテキストエリアはプロパティの代わりにページ本文として扱うようフラグを立てることができます。
- **Relationship Mappings** — Salesforce の参照または主従関係項目を Notion のリレーションプロパティにマッピングし、Notion 側でも親子構造が保たれるようにします。

アクションボタン：

- **Cancel** — 変更を破棄します（未保存の編集がある場合は確認ダイアログが表示されます）。
- **Test Connection** — Notion API への接続を検証します。
- **Save** — 設定をカスタムメタデータとしてデプロイします。

### Database Browser モーダル

**Browse Databases** をクリックすると、インテグレーションが参照可能なすべての Notion データベースを一覧表示するモーダルが開きます。データベース名または ID で検索し、選択して項目に反映できます。モーダルではデータベースのプロパティとその型もプレビュー表示されます。

### 自動型検出

UI は、選択した Salesforce 項目の型から Notion プロパティ型を提案します。

- STRING → rich_text
- EMAIL → email
- NUMBER / CURRENCY → number
- DATE / DATETIME → date
- BOOLEAN → checkbox
- PICKLIST → select
- REFERENCE → relation

Notion 側のスキーマが異なる場合は、提案を上書きできます。

### 同期のベストプラクティス

- 保存前に必ず **Test Connection** を実行してください。
- 少なくとも 1 つの Salesforce 項目を Notion の **title** プロパティにマッピングしてください — すべてのページにはタイトルが必要です。
- Salesforce ID プロパティは、本パッケージ専用のテキストプロパティを指すようにしてください。
- まずは少数の項目から始め、エンドツーエンドで同期を検証してから拡張してください。

## Widgets サブタブ

Widgets サブタブでは、管理者が `NotionWidget__mdt` を基にしたウィジェットを作成・管理できます。各ウィジェットは、アプリケーションビルダーで **Notion Widget** Lightning コンポーネントを使用して Lightning ページに埋め込むことができます。

### ウィジェット一覧

一覧には、設定済みの各ウィジェットの開発者名、対象 Notion データベース、任意のコンテキストオブジェクト、有効ステータス、および列／フィルタの件数が表示されます。**Edit** でウィジェットを開いたり、ゴミ箱アイコンで削除したりできます。新規作成するには **New Widget** をクリックします。

### ウィジェットの作成

1. **New Widget** をクリックします。
2. **Label** と **Developer Name** を入力します。開発者名は Lightning アプリケーションビルダーで選択する際に使用される名前です。
3. **Notion Database** — **Browse** をクリックしてソースデータベースを選択します。インテグレーションがそのデータベースにアクセスできる必要があります（Notion の `•••` → **Connections**）。
4. **Context Object** *(任意)* — ウィジェットを配置する Salesforce オブジェクト（レコードページ用）です。これを設定すると、ウィジェットはそのレコードに関連する Notion ページに絞り込まれます。
5. **Context Relation Property** *(任意)* — コンテキストレコードの Notion ページに紐付ける、対象データベース上の Notion リレーションプロパティ名です。設定すると、ウィジェットは Salesforce の関連リストのように動作します。
   - 行はコンテキストの Notion ページをリレーションに含むものに絞り込まれます。
   - **New** をクリックすると、そのリレーションが事前入力された下書きモーダルが開きます。
6. **Default Sort Property** / **Default Sort Direction** *(任意)* — テーブルに初期適用される並び順です。
7. **Page Size** — 1 ページあたりの行数（デフォルト 25、最大 100）。
8. **Show New Button** — ウィジェットから直接 Notion ページを作成できるインラインの「New」ボタンを切り替えます。
9. **Is Active** — 有効なウィジェットのみアプリケーションビルダーで選択できます。
10. **Columns** — 表示する Notion プロパティを選択し、順序と列幅を設定します。並び替えは保存時に保持されます。
11. **Filters** — 固定フィルタ（Notion プロパティの比較）を追加します。コンテキストフィルタがある場合はその上にレイヤーされます。
12. 保存します。

### Lightning ページへのウィジェット埋め込み

1. アプリケーションビルダーで対象ページ（レコードページ、アプリケーションページ、またはホームページ）を開きます。
2. **Custom** コンポーネントパネルから **Notion Widget** をページにドラッグします。
3. ウィジェットを選択した状態で、**Widget Configuration** プロパティに作成済みウィジェットの開発者名を設定します。この項目は有効な `NotionWidget__mdt` レコードを基にしたピックリストです。
4. ページを保存して有効化します。

### ウィジェットのベストプラクティス

- 開発者名は分かりやすく内容を表すものにしてください — Lightning ページを編集する管理者がピックリストで目にします。
- コンテキスト連動（関連リスト形式）のウィジェットを使用する場合、親レコードが既に Notion ページと同期済みであることを確認してください。そうでないと、ウィジェットには紐付け対象がありません。
- アプリケーションビルダーのピックリストが空の場合は、少なくとも 1 つのウィジェットで **Is Active = true** になっているか確認してください。

## Notion Navigation コンポーネント

ウィジェットに加え、本パッケージはレコードの Notion ページを直接開くための **Notion Navigation** Lightning コンポーネントを同梱しています。レコードページとフロー画面をサポートし、管理者 UI ではなくアプリケーションビルダー／フロービルダーでインスタンスごとに設定します。

主なプロパティ：

- **Card Title** / **Show Title** — Notion ブランドのヘッダー付き Lightning カードでアクションをラップするか、装飾なしでアクションを表示するかを切り替えます。
- **Navigation Style** — `button`（ラベル付きボタン）または `link`（インラインテキストリンク）。`button` ではラベルを非表示にしてアイコンのみのボタンにすることもできます。
- **Action Label** / **Show Action Label** / **Action Alignment** — ボタンまたはリンクに表示するテキスト、その表示有無、およびカード内での配置を制御します。
- **Sync Before Navigate** — メインクリック時のデフォルト同期動作です。オンにするとパッケージは Notion を開く前にレコードを同期し、オフにすると既存ページを直接開きます。
- **Show Sync Option** — オン（かつバリアントがラベル付きボタン）にすると、メインボタンの隣にシェブロンのドロップダウンが付加されます。ドロップダウンは **反対** の同期モード（たとえばデフォルトが同期なしの場合は *Open in Notion (With Sync)*）を提供するため、エンドユーザーは状態をまず切り替えなくても、クリックごとに別の動作を選択できます。これをオフにすると、デザイナーで指定したデフォルト動作に固定され、代替動作は完全に非表示になります。

分割ボタンのドロップダウンはラベル付きボタンバリアントのときのみ表示されます。リンクスタイルとアイコンのみのボタンでは、メインアクションのみが表示されます。

## Notion Sync Log タブ

**Notion Sync Log** タブには、直近の同期試行が新しい順に表示されます。任意のログ行をクリックすると、次の情報を確認できます。

- レコード ID とオブジェクト型
- 操作種別（CREATE / UPDATE / DELETE）
- ステータス（Success / Failed / Retrying）
- Notion ページ ID（成功時）
- エラーメッセージ（失敗時）
- タイムスタンプ

リストビューは数式項目を使用して日付の降順並び替えを有効にしています。

## 権限エラー

`Notion_Sync_Admin` を持たないユーザーが管理者 UI を開くと、「アクセス拒否」画面が表示され、管理者に連絡して **Notion Sync Administrator** 権限セットを要求するように案内されます。同じチェックは UI の背後にあるすべての Apex メソッドでもカスタム権限 `Notion_Sync_Admin` を用いて適用されるため、UI を迂回することはできません。

## トラブルシューティング

### Notion データベースが表示されない

- 指定ログイン情報に有効な API トークンが設定されていることを確認してください。
- インテグレーションがデータベースに接続されていることを確認してください（Notion の `•••` → **Connections**）。
- 詳細なエラー内容を得るには **Test Connection** を実行してください。

### メタデータの保存が失敗する

- ユーザーには「アプリケーションのカスタマイズ」と「メタデータの変更」権限が必要です（Notion Sync Administrator 権限セットに含まれます）。
- 開発者名は一意である必要があります — 保存時に競合が報告された場合は別の名前を選択してください。
- エラーが不明瞭な場合はデバッグログを確認してください。

### 項目マッピングが同期されない

- Notion プロパティ名は大文字小文字と空白を区別します — 完全に一致しているか確認してください。
- Notion プロパティ型が Salesforce 項目型と互換性があることを確認してください。
- 項目レベルセキュリティでインテグレーションユーザーが項目を読み取れることを確認してください。

### アプリケーションビルダーのウィジェット設定ピックリストが空

- 少なくとも 1 つのウィジェットで **Is Active = true** になっている必要があります。
- 変更が反映されていない場合は、ウィジェットを再保存するとピックリストが更新されます。
