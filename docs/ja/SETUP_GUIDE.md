# セットアップガイド

このガイドでは、Salesforce 管理者向けに **Notion Salesforce Sync** パッケージのインストール手順と、同期・Notion ウィジェット・その両方を利用するための設定手順を説明します。

共通手順 (1〜3) はパッケージを利用するすべてのケースで必須です。手順 3 まで完了したら、必要な構成に応じて以下のパスに進んでください。

- **パス A — 同期の設定**: フロートリガによって Salesforce レコードを Notion データベースに送信します。
- **パス B — ウィジェットの設定**: Notion データベースのビューを Lightning ページ内に埋め込みます。

---

## 前提条件

- **システム管理者** 権限を持つ Salesforce 組織 (本番、Sandbox、または Developer Edition)。
- **インテグレーション** を作成し、データベースへのアクセス権限を付与できる Notion ワークスペース。
- モダンブラウザ。CLI アクセスは任意です — 以下のすべての手順には UI による代替手段があります。

---

## 手順 1 — パッケージのインストール

このパッケージは `notionsync` 名前空間を持つマネージド 2GP として配布されています。

### インストール URL (最新リリースバージョン)

対象組織にログインした状態で、以下の URL を開いてください。特別な理由がない限り **管理者のみインストール** を選択してください。

```
https://login.salesforce.com/packaging/installPackage.apexp?p0=04tgL000000GJhpQAG
```

Sandbox 環境の場合は、`login.salesforce.com` を `test.salesforce.com` に置き換えてください。

### CLI による代替手段

```bash
sf package install \
  --package 04tgL000000GJhpQAG \
  --target-org <your-org-alias> \
  --wait 20
```

インストール後、App Launcher から **Notion Sync** アプリケーションを利用できるようになります。

---

## 手順 2 — Notion の準備

### 2.1 内部インテグレーションを作成する

1. ワークスペースのオーナーとして Notion にサインインし、<https://www.notion.so/my-integrations> を開きます。
2. **New integration** をクリックします。
3. 名前 (例: `Salesforce Sync`) を設定し、接続するワークスペースを選択します。
4. 送信後、**Internal Integration Token** (先頭が `ntn_` または `secret_`) をコピーします。このトークンはパスワードと同様に取り扱ってください — 手順 3 で Salesforce に登録します。

### 2.2 インテグレーションにデータベースへのアクセス権を付与する

パッケージが読み書きする **すべての** Notion データベースについて、以下を実施してください。

1. Notion でデータベースのページを開きます。
2. 右上の `•••` メニュー → **Connections** → **Add connections** をクリックします。
3. 作成したインテグレーションを選択し、**Confirm** をクリックします。

### 2.3 Salesforce ID プロパティを追加する (同期のみ)

パス A (同期) を利用する場合、同期されたレコードを受け取る各 Notion データベースには、Salesforce レコード ID を格納するプロパティが必要です。パッケージはこのプロパティを使用して既存のページを検出し、重複を防止します。

1. 対象の Notion データベースを開きます。
2. 新しいプロパティを追加します (推奨名: `Salesforce ID`、種別: **Text**)。
3. 同期対象のすべてのデータベースで同じ作業を繰り返します。

このプロパティは、手順 6 で同期を設定する際に名前で選択します。

> ウィジェットのみの構成 (パス B) では、この設定は不要です。ウィジェットは、インテグレーションがアクセス可能な任意の Notion データベースを読み取ります。

---

## 手順 3 — Salesforce のログイン情報と権限の設定

### 3.1 Notion API キーを登録する

パッケージには、`Notion Credential` という名前の **外部ログイン情報** と、`NotionIntegration` という名前の **指定プリンシパル** が同梱されています。API トークンを紐付けるだけで利用できます。

1. 設定 → **指定ログイン情報** → **外部ログイン情報** タブ → **Notion Credential**。
2. **プリンシパル** セクションで、`NotionIntegration` の行をクリックします。
3. **認証パラメータ** で **新規** をクリックします。
4. 以下を追加します。
   - **名前**: `SecretKey`
   - **値**: 手順 2.1 で取得した Notion インテグレーショントークン
5. 保存します。

### 3.2 権限セットを割り当てる

パッケージには 3 つの権限セットが含まれています。それぞれを必要なユーザーに割り当ててください。

| 権限セット | ラベル | 対象ユーザー |
|---|---|---|
| `Notion_Sync_Admin` | Notion Sync Administrator | 管理 UI を通じてマッピング、ウィジェット、ログイン情報を設定する管理者。 |
| `Notion_Integration_User` | Notion Integration User | レコードの変更によって同期をトリガする (フローを起動する) すべてのユーザー。 |
| `Notion_Widget_User` | Notion Widget User | Lightning ページ上で埋め込まれた Notion ウィジェットを閲覧するだけのエンドユーザー。 |

割り当て手順:

1. 設定 → **権限セット** → 権限セット名をクリックします。
2. **割り当ての管理** → **割り当て追加** → ユーザーを選択 → **割り当て** をクリックします。

> 1 人のユーザーに複数の権限セットを割り当てることができます。同期もトリガする管理者には、Sync Administrator と Integration User の両方が必要です。

### 3.3 接続を確認する

1. App Launcher → **Notion Sync** を開きます。
2. **Notion Sync Admin** タブで、(右上の) **Test Connection** をクリックします。
3. アクセス可能なデータベース一覧と成功メッセージが表示されれば成功です。表示されない場合は [トラブルシューティング](#トラブルシューティング) を参照してください。

ここまでで、パッケージのインストールと認証が完了しました。**パス A**、**パス B**、または両方に進んでください。

## パス A — 同期の設定

目的: Salesforce レコードに対応する Notion ページを自動的に作成、更新、削除します。

### A.1 同期設定を作成する

1. **Notion Sync** アプリケーション → **Notion Sync Admin** タブを開きます。
2. **Sync** サブタブに切り替えます。
3. **New Sync Configuration** をクリックします。
4. Salesforce オブジェクト (例: `Account`) を選択します。
5. **Browse Databases** をクリックし、手順 2.3 で準備した Notion データベースを選択します。
6. **Salesforce ID Property Name** で、手順 2.3 で追加したプロパティ (例: `Salesforce ID`) を選択します。
7. 保存します。

### A.2 項目をマッピングする

保存した設定で、以下を実施します。

1. **Field Mappings** セクションを開きます。
2. 各 Salesforce 項目について、Notion プロパティへのマッピングを追加します。UI は互換性のある Notion プロパティの種別を自動で提案します。
3. 少なくとも 1 つのマッピングが Notion の **Title** プロパティを対象としていることを確認してください。
4. (任意) **Body Content** フラグを使用して、ロングテキストエリアをページ本文にマッピングします。
5. (任意) **Relationship Mappings** を設定し、参照関係や主従関係をデータベース間の Notion リレーションに変換します。
6. 保存します。UI は変更をカスタムメタデータとしてデプロイします。

管理 UI の詳細は [Admin UI Usage](./ADMIN_UI_USAGE.md) を参照してください。

### A.3 フロートリガを作成する

パッケージには、オブジェクトごとにコピーして利用できるテンプレートフローが含まれています。完全な手順は [Flow Configuration](./FLOW_CONFIGURATION.md) に記載されています。概要は以下の通りです。

1. `NotionSync_Template_CreateUpdate.flow-meta.xml` と `NotionSync_Template_Delete.flow-meta.xml` をコピーし、対象オブジェクト用にリネームします。
2. `[ObjectApiName]` プレースホルダーを、オブジェクトの API 参照名 (例: `Account`) に置き換えます。
3. フローをデプロイし、設定 → **フロー** で両方を **有効化** します。

### A.4 同期を確認する

1. 同期対象オブジェクトの新規レコード (例: 新規 Account) を作成します。
2. 対応する Notion データベースを開き、数秒以内にページが表示されることを確認します。
3. レコードを更新し、次に削除して、Notion が各変更を反映することを確認します。
4. 反映されない項目がある場合は、Notion Sync アプリケーション内の **Notion Sync Logs** タブを開き、**Status** および **Error Message** 列を確認してください。

## パス B — ウィジェットの設定

目的: Salesforce のレコード、アプリケーション、またはホームページ上に Notion ページのリストを埋め込みます。ウィジェットは関連リストとしても機能でき、現在の Salesforce レコードに対応する Notion ページに関連するページのみをフィルタリングして表示できます。

### B.1 ウィジェット設定を作成する

1. **Notion Sync** アプリケーション → **Notion Sync Admin** タブを開きます。
2. **Widgets** サブタブに切り替えます。
3. **New Widget** をクリックします。
4. 以下を入力します。
   - **Label** および **Developer Name** — App Builder で選択する際に使用するのは Developer Name です。
   - **Notion Database** — **Browse** をクリックして、ソースとなるデータベースを選択します。
   - **Context Object** (任意) — ウィジェットをレコードページに配置し、関連レコードの Notion ページでフィルタリングしたい場合に設定します。
   - **Context Relation Property** (任意) — コンテキストレコードの Notion ページとのリンクに使用する Notion リレーションプロパティの名前です。設定すると、ウィジェットは関連リストのように動作し、行がフィルタリングされ、**New** ボタンはこのリレーションが事前入力されたページを作成します。
   - **Default Sort**、**Page Size**、**Show New Button** — 任意の動作調整。
5. **Columns** — 表示する Notion プロパティとその順序を選択します。
6. **Filters** — コンテキストフィルタに加えて、任意の固定フィルタを追加します。
7. 保存します。

### B.2 ウィジェットを Lightning ページに配置する

1. ウィジェットを表示したい Lightning ページを開きます (App Builder → レコードページ、アプリケーションページ、ホームページから **ページを編集**)。
2. 左側の **カスタム** コンポーネントパネルから、**Notion Widget** をキャンバスにドラッグします。
3. ウィジェットを選択した状態で、**Widget Configuration** を B.1 で設定した Developer Name に設定します (この項目は選択リストです)。
4. ページを保存し、有効化します。

### B.3 ウィジェットを確認する

1. ウィジェットを配置した Lightning ページを開きます。
2. Notion データベースの行がウィジェットに表示されることを確認します。コンテキストにバインドされたウィジェット (B.1) の場合、現在のレコードの Notion ページにリンクされている行のみが表示されるはずです。
3. **New** ボタンが表示されている場合、クリックするとドラフトモーダルが開き、リレーションプロパティが事前入力されます。

> **ヒント — ナビゲーションにも**: パッケージには、レコードページまたはフロー画面用の **Notion Navigation** コンポーネントが含まれており、レコードの Notion ページを直接開くことができます。ラベル付きボタンのバリアントは分割ボタンとしてレンダリングされ、エンドユーザーはクリックごとにドロップダウンから反対の同期モード (例: *Open in Notion (With Sync)*) を選択できます。同じ App Builder パネルからドラッグして、ラベル、配置、デフォルトの同期動作、および右側のペインで代替アクションを提供するかどうかを設定してください。

## トラブルシューティング

### 「ログイン情報にアクセスできませんでした」
現在のユーザーが指定ログイン情報を読み取れません。
- `NotionIntegration` プリンシパルに `SecretKey` パラメータが設定されていることを確認してください (手順 3.1)。
- 同期をトリガするユーザーに **Notion Integration User** 権限セット (または管理操作用に **Notion Sync Administrator** 権限セット) を割り当ててください。

### 「Unauthorized endpoint」 または Notion からの 401 エラー
トークンが未設定、誤り、または失効しています。
- <https://www.notion.so/my-integrations> からトークンを再度貼り付けてください。
- インテグレーションが対象データベースへのアクセス権を保持していることを確認してください (Notion の `•••` → **Connections**)。

### 同期が実行されない
- 設定 → **フロー** で、対象オブジェクトの CreateUpdate および Delete フローの両方が **有効** になっていることを確認してください。
- **Notion Sync Logs** で失敗を確認してください — Error Message 列で、検証、マッピング、または Notion API のどこで失敗したかを判別できます。
- レコードを編集したユーザーに **Notion Integration User** 権限セットが割り当てられていることを確認してください。

### ウィジェットに「アクセス拒否」または空のリストが表示される
- 閲覧者に **Notion Widget User** (または **Notion Sync Administrator**) を割り当ててください。
- Notion データベースがインテグレーションと共有されていることを確認してください (手順 2.2)。
- コンテキストにバインドされたウィジェットの場合、フィルタの対象とするために、現在のレコードに対応する同期済みの Notion ページがすでに存在している必要があります。

### App Builder のウィジェット選択リストが空になっている
- 少なくとも 1 つのウィジェット設定で **Is Active = true** になっている必要があります。
- メタデータをデプロイした直後の場合、管理画面で再度保存が必要となる場合があります。
